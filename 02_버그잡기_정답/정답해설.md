# 4교시 정답해설 — 버그 5개

## 버그 1 — 오타로 인한 null 접근

**증상**
페이지를 열면 잔액이 화면에 표시되지 않고, 개발자 도구 콘솔에 빨간 에러가 뜬다.

```
Uncaught TypeError: Cannot set properties of null (setting 'textContent')
```

**원인**
`renderBalance()` 함수 안에서 `document.getElementById("balance")` 라고 써야 하는데
`document.getElementById("blance")` 로 오타가 났다. HTML에는 `id="balance"` 인 요소만 있으므로
`getElementById("blance")` 는 `null` 을 반환하고, 그 `null` 에 `.textContent` 를 대입하려다 에러가 난다.

**고친 코드**

```javascript
// before
function renderBalance() {
  const balanceEl = document.getElementById("blance");
  balanceEl.textContent = formatCurrency(ACCOUNTS[0].balance);
}

// after
function renderBalance() {
  const balanceEl = document.getElementById("balance");
  balanceEl.textContent = formatCurrency(ACCOUNTS[0].balance);
}
```

**AI에게 물어보는 좋은 프롬프트 예시**
> "잔액이 화면에 안 나오고, 콘솔에 `Cannot set properties of null (setting 'textContent')` 에러가 떠. app.js의 renderBalance 함수를 보고 원인을 찾아줘."

**AI가 자주 하는 실수**
`querySelector`/`getElementById` 오타는 AI가 코드를 눈으로 훑기만 하면 놓치기 쉽다. HTML의 `id` 값과
JS에서 참조하는 문자열을 한 글자씩 대조해 달라고 구체적으로 요청하면 더 잘 찾는다.

## 버그 2 — 이벤트 핸들러에 괄호

**증상**
페이지를 열자마자 "10,000원이 입금되었습니다" 알림이 한 번 뜨고(즉, 묻지도 않았는데 입금이 실행됨),
그 이후로 입금 버튼을 아무리 눌러도 아무 반응이 없다. 콘솔에는 에러가 뜨지 않는다.

**원인**

```javascript
depositBtn.addEventListener("click", handleDeposit());
```

`handleDeposit()` 처럼 함수 이름 뒤에 괄호를 붙이면, 그 순간 함수가 **바로 실행**된다.
`addEventListener` 의 두 번째 인자로는 "클릭했을 때 실행할 함수 자체"가 들어가야 하는데,
`handleDeposit()` 의 실행 결과(값, 여기서는 `undefined`)가 들어가 버린다. 그래서 리스너로는
아무 함수도 등록되지 않아 이후 클릭이 먹지 않는다.

**고친 코드**

```javascript
// before
depositBtn.addEventListener("click", handleDeposit());

// after
depositBtn.addEventListener("click", handleDeposit);
```

**AI에게 물어보는 좋은 프롬프트 예시**
> "입금 버튼을 눌러도 반응이 없는데, 페이지를 열면 입금이 한 번 자동으로 실행돼. addEventListener를 쓰는 부분을 확인해줘."

**AI가 자주 하는 실수**
없음 — 이 패턴은 AI가 매우 잘 찾아내는 전형적인 실수다. 다만 학생이 증상만 보고는
"클릭이 안 먹는다"에만 집중해서, "페이지를 열자마자 한 번 실행된다"는 단서를 AI에게
전달하지 않으면 AI도 원인을 바로 짚지 못할 수 있다.

## 버그 3 — 금액을 실수로 계산

**증상**
"이자 계산하기" 버튼을 누르면 이자와 잔액에 `26652.500000000004원` 처럼 이상한 소수점이 붙어서 표시된다.

**원인**

```javascript
function calcInterest(balance, rate) {
  return balance * rate;
}
// 호출: calcInterest(1523000, 0.0175)
```

자바스크립트의 숫자는 2진 부동소수점(IEEE 754)으로 저장되기 때문에, `0.0175` 같은 10진 소수는
정확히 표현되지 않는다. 그래서 `1523000 * 0.0175` 를 계산하면 수학적으로는 `26652.5` 지만
실제로는 `26652.500000000004` 처럼 미세한 오차가 남는다. 이 값을 그대로 잔액에 더하고
화면에 표시했기 때문에 원 단위여야 할 금액에 소수점이 붙어버린다.

**고친 코드**

```javascript
// before
const interest = calcInterest(ACCOUNTS[0].balance, rate);
const newBalance = ACCOUNTS[0].balance + interest;

// after
const interest = Math.round(calcInterest(ACCOUNTS[0].balance, rate));
ACCOUNTS[0].balance += interest;
```

**AI에게 물어보는 좋은 프롬프트 예시**
> "이자를 계산해서 잔액에 더했더니 1558029.0000000002 같은 값이 나와. calcInterest 함수와 그걸 호출하는 부분을 보고 원 단위 정수로 고쳐줘."

**AI가 자주 하는 실수 (중요)**
AI에게 이 문제를 그냥 물어보면 `toFixed(2)` 를 제안하는 경우가 많다. 하지만 `toFixed(2)` 는
**정답이 아니다.**

- `toFixed(2)` 는 숫자가 아니라 **문자열**을 반환한다. 이후 이 값으로 다시 계산을 하면
  숫자가 아니라 문자열끼리 이어 붙는(concatenation) 버그가 생길 수 있다.
- 소수점 2자리까지 남기는 것이지, 소수점을 없애는 게 아니다. `26652.50` 처럼 여전히
  소수점이 남는다.
- 은행 업무에서 원화 금액은 **원 단위 정수**로 다룬다(1원 미만은 존재하지 않는다).

그래서 정답은 `Math.round(balance * rate)` 로 반올림해서 정수로 만드는 것이다.
학생이 `toFixed(2)` 로 고친 결과 화면에 `26652.5` 나 `"26652.50"` 같은 값이 여전히
남아있는지 **직접 콘솔에서 `typeof` 를 찍어보게 하는 것**이 이 실습의 핵심이다.

```javascript
console.log(typeof (26652.5).toFixed(2)); // "string" — 숫자가 아니다!
console.log(Math.round(26652.5));          // 26653 — 원하는 정수
```

## 버그 4 — 비동기 결과를 await 없이 사용

**증상**
"오늘의 환율" 자리에 숫자 대신 `[object Promise]원` 이라고 표시된다.

**원인**

```javascript
async function fetchExchangeRate() {
  return new Promise((resolve) => setTimeout(() => resolve(1384), 500));
}

const rate = fetchExchangeRate();
document.querySelector("#exchangeRate").textContent = rate + "원";
```

`fetchExchangeRate()` 는 `async` 함수이므로 항상 **Promise 객체**를 반환한다. 이 함수가
실제로 값(1384)을 만들어내는 데는 0.5초가 걸리는데, 코드에서는 그 결과를 기다리지 않고
Promise 객체 자체를 `rate` 에 담아 바로 화면에 넣어버렸다. 그래서 숫자가 아니라
"이것은 Promise 객체입니다"라는 뜻의 문자열 `[object Promise]` 가 찍힌다.

**고친 코드**

```javascript
// before
const rate = fetchExchangeRate();
document.querySelector("#exchangeRate").textContent = rate + "원";

// after (방법 1: .then 사용)
fetchExchangeRate().then((rate) => {
  document.querySelector("#exchangeRate").textContent = formatCurrency(rate);
});

// after (방법 2: async 함수 안에서 await 사용)
async function showExchangeRate() {
  const rate = await fetchExchangeRate();
  document.querySelector("#exchangeRate").textContent = formatCurrency(rate);
}
showExchangeRate();
```

**AI에게 물어보는 좋은 프롬프트 예시**
> "환율 자리에 숫자 대신 [object Promise]라고 떠. fetchExchangeRate 함수를 어떻게 부르는지 봐줘."

**AI가 자주 하는 실수**
`await` 을 최상위(top-level)에 그냥 추가해서 `const rate = await fetchExchangeRate();` 로
고쳐주는 경우가 있는데, 이 프로젝트처럼 `<script src="app.js">` (모듈이 아닌 일반 스크립트)에서는
최상위 `await` 이 지원되지 않아 문법 에러가 난다. `.then()` 을 쓰거나, `async` 함수로 감싼 뒤
그 함수를 호출하는 방식으로 고쳐야 한다.

## 버그 5 — CSS: position 없이 z-index

**증상**
"이체 확인" 버튼을 눌러도 확인 창이 보이지 않는다(또는 페이지 맨 아래 이상한 위치에 나타난다).
콘솔에는 아무 에러도 뜨지 않는다.

**원인**

```css
/* before */
.modal-overlay {
  z-index: 500;
  top: 0;
  left: 0;
  width: 100%;
  height: 100%;
  background: rgba(17, 24, 39, 0.55);
}
.modal {
  z-index: 600;
  ...
}
```

`z-index` 와 `top`/`left` 는 그 요소가 `position: relative` / `absolute` / `fixed` /
`sticky` 중 하나로 지정되어 있을 때만 의미가 있다. `position` 을 아예 지정하지 않으면
(기본값 `static`) `z-index` 와 `top`/`left` 값은 브라우저가 조용히 무시한다. 그래서
오버레이가 화면 전체를 덮는 반투명 배경으로 뜨지 못하고, 확인 창도 페이지 본문 흐름 속
어딘가에 평범한 박스로 끼어 들어가 버린다. **CSS는 이런 실수를 해도 에러를 내지 않는다.**

**고친 코드**

```css
/* after */
.modal-overlay {
  position: fixed;
  z-index: 500;
  top: 0;
  left: 0;
  width: 100%;
  height: 100%;
  background: rgba(17, 24, 39, 0.55);
  display: flex;
  align-items: center;
  justify-content: center;
}
.modal {
  position: relative;
  z-index: 600;
  ...
}
```

**AI에게 물어보는 좋은 프롬프트 예시**
> "이체 확인 버튼을 누르면 modalOverlay에서 hidden 클래스를 지우는 JS는 실행되는데, 화면 중앙에 반투명 배경과 함께 흰색 카드가 떠야 하는데 안 보여. style.css의 .modal-overlay, .modal 부분을 봐줘."
(어떻게 보여야 하는지를 구체적으로 말해줄수록 AI가 CSS 문제를 더 잘 찾는다.)

**AI가 자주 하는 실수**
`z-index` 값을 더 큰 숫자로 올리라고 제안하는 경우가 있는데, `position` 이 빠진 상태에서는
`z-index` 를 아무리 높여도 효과가 없다. 근본 원인은 숫자 크기가 아니라 `position` 누락이다.

## 강사 메모 — 버그 유형 정리

| 버그 | 증상 유형 | 핵심 교훈 |
|---|---|---|
| 1. 오타 (`blance`) | 콘솔 에러 | 에러 메시지를 읽으면 원인 위치를 특정할 수 있다 |
| 2. 괄호 (`handleDeposit()`) | 에러 없는 오동작 | 에러가 없다고 정상은 아니다. 재현 조건을 정확히 말해야 AI가 찾는다 |
| 3. 실수 연산 (`0.0175` 오차) | 계산 오류 | 컴퓨터의 소수 계산은 정확하지 않다. 금액은 정수로 다뤄야 한다 |
| 4. Promise 미대기 | 비동기 | `async` 함수는 항상 Promise를 반환한다. `await`/`.then()`이 필요하다 |
| 5. `position` 없는 `z-index` | CSS (에러 없음) | CSS는 문법이 틀려도 에러를 내지 않는다. "어떻게 보여야 하는지"를 말로 설명해야 한다 |
